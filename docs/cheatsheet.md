# Шпаргалка

Всё, что на экзамене понадобится быстро и чего не хочется вспоминать по
памяти. Источник истины для правил валидации —
`packages/shared/src/validation.ts`; здесь они продублированы для чтения
глазами.

---

## 1. Правила валидации — дословно из ТЗ

| Поле    | Правило                               | Регулярное выражение              |
| ------- | ------------------------------------- | --------------------------------- |
| Логин   | латиница и цифры, не менее 6 символов | `/^[A-Za-z0-9]{6,}$/`             |
| Пароль  | минимум 8 символов                    | длина, без шаблона                |
| ФИО     | символы кириллицы и пробелы           | `/^[А-Яа-яЁё\s]+$/`               |
| Телефон | строго `8(XXX)XXX-XX-XX`              | `/^8\(\d{3}\)\d{3}-\d{2}-\d{2}$/` |
| Почта   | адрес электронной почты               | `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`    |

Две ловушки, на которых теряют баллы:

- **`Ё` и `ё`** в диапазон `А-Яа-я` не входят — их нужно дописывать явно,
  иначе «Алёна» не пройдёт проверку;
- **скобки в телефоне экранируются** — `8\(\d{3}\)`, иначе это группа.

Оценка в отзыве — целое число от 1 до 5.

## 2. Тексты из ТЗ — сверять посимвольно

Эксперт сверяет дословно, поэтому переформулировать нельзя.

| Где                | Текст                                             |
| ------------------ | ------------------------------------------------- |
| Кнопка регистрации | `Создать пользователя`                            |
| Ссылка со входа    | `Еще не зарегистрированы? Регистрация`            |
| Способы оплаты     | `При очном посещении`, `Переводом по системе СБП` |
| Статусы заявки     | `Новая`, `Мероприятие назначено`, `Завершено`     |
| Администратор      | логин `Conf2027`, пароль `Demo77`                 |

Обратите внимание: в ссылке со входа — `Еще`, без точек над «е». Так в ТЗ.

Из трёх статусов администратор выставляет руками не все — «Новая»
присваивается при создании заявки.

## 3. Команды

### Каждый день

| Команда          | Что делает                                     |
| ---------------- | ---------------------------------------------- |
| `pnpm dev`       | поднимает общий пакет, бэкенд и фронтенд разом |
| `pnpm build`     | собирает всё                                   |
| `pnpm test`      | модульные тесты обоих приложений               |
| `pnpm e2e`       | девять сквозных проверок в браузере            |
| `pnpm lint`      | ESLint                                         |
| `pnpm lint:fsd`  | проверка слоёв фронтенда (steiger)             |
| `pnpm typecheck` | типы без сборки                                |
| `pnpm format`    | Prettier по всему дереву                       |

### База данных

| Команда                                          | Что делает                            |
| ------------------------------------------------ | ------------------------------------- |
| `pnpm db:up`                                     | поднимает PostgreSQL и MySQL в Docker |
| `pnpm db:reset`                                  | сносит данные и поднимает заново      |
| `pnpm db:logs`                                   | логи PostgreSQL                       |
| `pnpm --filter @kim/backend db:migrate`          | применяет миграции                    |
| `pnpm --filter @kim/backend db:migrate:generate` | создаёт миграцию по сущностям         |
| `pnpm --filter @kim/backend db:schema:log`       | показывает расхождение базы и кода    |
| `pnpm --filter @kim/backend db:seed`             | справочные данные и администратор     |
| `pnpm erd`                                       | ER-диаграмма по живой базе            |

**Про миграции на экзамене:** они не обязательны. Схему быстрее менять через
`DB_SYNCHRONIZE=true`, а миграцию сгенерировать один раз в конце. Подробно —
в [exam-playbook.md](./exam-playbook.md).

### Офлайн

| Команда             | Что делает                               |
| ------------------- | ---------------------------------------- |
| `pnpm offline:prep` | документация + колёса + архив, всё разом |
| `pnpm bundle`       | только архив для флешки                  |
| `pnpm stack:docs`   | документация по стеку в `docs/stack/`    |

### Запасной бэкенд на Python

| Команда              | Что делает                                            |
| -------------------- | ----------------------------------------------------- |
| `pnpm py:install`    | окружение и зависимости (офлайн — из `wheels`)        |
| `pnpm py:dev`        | FastAPI на порту 3001                                 |
| `pnpm py:seed`       | справочные данные в MySQL                             |
| `pnpm shared:python` | переносит правила валидации из `@kim/shared` в Python |

Переключить фронтенд на него: `API_PROXY_TARGET=http://localhost:3001 pnpm dev:front`.

## 4. Полезное из psql

```bash
psql postgresql://kim:kim@localhost:5432/conferences

\dt                      -- таблицы
\d applications          -- структура таблицы
\di                      -- индексы
select * from users limit 5;
\q
```

Проверить, что пароли не лежат открытым текстом:

```sql
select login, left(password_hash, 12) from users limit 3;
-- ожидаем scrypt$16384$…
```

## 5. Когда что-то не работает

| Симптом                                   | Причина и что делать                                                     |
| ----------------------------------------- | ------------------------------------------------------------------------ |
| `role "kim" does not exist`               | локальный PostgreSQL перехватил порт 5432 — [db-setup.md](./db-setup.md) |
| `curl` на localhost отдаёт отказ прокси   | `export NO_PROXY=localhost,127.0.0.1`                                    |
| Порт занят                                | `lsof -nP -iTCP:3000 -sTCP:LISTEN`                                       |
| «Слишком много попыток» при отладке       | `AUTH_THROTTLE_LIMIT=1000 pnpm dev:back`                                 |
| Фронтенд не видит API                     | проверить `API_PROXY_TARGET` и что бэкенд поднялся                       |
| Схема базы разошлась с кодом              | `pnpm --filter @kim/backend db:schema:log`                               |
| `pnpm` отсутствует на машине              | `node scripts/npm-fallback.mjs` — [exam-playbook.md](./exam-playbook.md) |
| Нет git-репозитория, `pnpm install` падал | уже учтено: `prepare` пропускает хуки вне git                            |
