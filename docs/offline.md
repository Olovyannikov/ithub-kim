# Офлайн и развёртывание на чужой машине

На площадке ДЭ интернета нет. Значит, всё, что обычно подтягивается из сети —
зависимости, документация, шрифты — должно приехать с собой. Этот документ
описывает, как собрать такой комплект дома и как развернуть его на площадке.

Все цифры ниже — замеренные, на MacBook с SSD. На более медленной машине
порядок величин сохранится.

---

## 1. Дома: собрать комплект

```bash
pnpm offline:prep
```

Одна команда делает четыре вещи:

| Шаг                      | Что делает                                                     | Сколько |
| ------------------------ | -------------------------------------------------------------- | ------- |
| `pnpm stack:docs`        | качает документацию Effector, NestJS, TypeORM, React           | ~2 мин  |
| `pnpm mantine:docs:full` | качает полный справочник Mantine (~4,6 МБ)                     | ~30 с   |
| `pnpm py:wheels`         | складывает колёса запасного бэкенда в `apps/backend-py/wheels` | ~5 с    |
| `pnpm bundle`            | пакует всё в `offline/kim-offline-<дата>.tgz`                  | ~35 с   |

На выходе один файл около 100 МБ. Влезает на любую флешку, копируется за
секунды.

### Что внутри

- исходники проекта;
- **`node_modules` целиком** — поэтому на площадке не нужен ни `pnpm install`,
  ни сеть, ни pnpm store;
- `apps/backend-py/wheels` — зависимости запасного бэкенда на Python;
- `docs/stack/` — офлайн-документация по всему стеку;
- всё остальное из репозитория: ADR, план экзамена, схема БД, ER-диаграмма.

Чего внутри **нет** и почему:

- `.git` — на площадке нужен свежий репозиторий, а не наша история;
- `apps/backend-py/.venv` — виртуальное окружение Python не переносится, в
  шебангах его скриптов записаны абсолютные пути. Поэтому и нужны колёса;
- собранные `dist` — они пересобираются за семь секунд.

### Проверка, а не обещание

`pnpm bundle` не просто пакует архив: он распаковывает его во временный
каталог и запускает там сборку. Если архив получился битым, вы узнаете об
этом дома, а не на площадке.

Эта проверка появилась не на пустом месте. Первая версия скрипта исключала
из архива каталоги `dist` — и bsdtar вырезал `dist` не только у нас, но и
**внутри `node_modules`**, где он есть у половины пакетов. Архив собирался,
весил сколько надо и разворачивался, а сборка падала на отсутствующем модуле.
Причина: односегментный паттерн (`./dist`) libarchive матчит по имени файла в
любом месте дерева. Многосегментные (`./apps/backend/dist`) матчатся точно —
в скрипте теперь только такие.

## 2. На площадке: развернуть

Замер полного цикла из архива — распаковка, сборка, база, запуск, сквозная
проверка в браузере:

```
[0s]   распаковка архива
[6s]   сборка
[13s]  миграции и справочные данные
[18s]  запуск бэкенда и фронтенда
[25s]  стек отвечает
[73s]  девять сквозных проверок пройдены
```

До работающего приложения — **полминуты**. «Десять минут» из плана — это запас
на незнакомую машину, а не реальная длительность.

### По шагам

```bash
# 1. Распаковать
mkdir -p ~/project && tar -xzf kim-offline-*.tgz -C ~/project && cd ~/project

# 2. Поднять базу (см. docs/db-setup.md — там три способа)
docker compose up -d postgres

# 3. Схема и справочные данные
pnpm --filter @kim/backend db:migrate
pnpm --filter @kim/backend db:seed

# 4. Запустить
pnpm dev
```

Открыть `http://localhost:5173`. Администратор — `Conf2027` / `Demo77`.

### Проверить, что всё поднялось

```bash
pnpm e2e
```

Девять сквозных проверок в настоящем браузере: защита маршрутов, обе формы,
полный сценарий «регистрация → заявка → смена статуса → отзыв» и мобильный
макет. Если они зелёные — приложение работает целиком, а не только собирается.

## 3. Что может пойти не так

### Прокси перехватывает localhost

Ловушка, на которую легко потерять время. Если на машине настроен
корпоративный прокси (`http_proxy` / `https_proxy`), `curl` потащит через него
**и запросы на localhost** — и получит отказ от прокси, хотя сервис работает.

```bash
export NO_PROXY=localhost,127.0.0.1
# либо точечно:
curl --noproxy '*' http://localhost:3000/api/health
```

Браузер при этом может работать нормально — расхождение сбивает с толку.

### Чужая платформа

В `node_modules` лежат бинарники под ту ОС и архитектуру, где собирался архив
(esbuild, sharp, lightningcss). Колёса Python — тоже. Между macOS arm64 и,
скажем, Linux x64 архив **не переносится**.

Если на площадке другая платформа:

1. `pnpm install` с сетью, если сеть всё-таки есть;
2. если нет сети и нет pnpm — `node scripts/npm-fallback.mjs`, см. раздел
   «Если на машине нет pnpm» в [exam-playbook.md](./exam-playbook.md);
3. запасной бэкенд на Python ставится из колёс только для своей платформы;
   на чужой — `pip install -r requirements.txt` с сетью.

Это стоит выяснить у преподавателя **заранее**: какая ОС на площадке. От
ответа зависит, на какой машине собирать архив.

### Нет Docker

Docker на площадке может быть не установлен или требовать прав. В
[db-setup.md](./db-setup.md) описаны ещё два способа: локально установленный
PostgreSQL и MySQL. КИМ называет из СУБД именно MySQL — запасной путь на
MySQL проверен целиком, включая сквозные проверки (ADR-0011).

### Порт 5432 уже занят

Классика: локальный PostgreSQL слушает `127.0.0.1:5432`, Docker поднимает свой
на `*:5432`, подключение уходит не туда и выдаёт `role "kim" does not exist`.
Разбор — в [db-setup.md](./db-setup.md).

## 4. Документация без интернета

После `pnpm stack:docs` в `docs/stack/` лежит:

| Что                | Формат                             |
| ------------------ | ---------------------------------- |
| Effector           | один файл `llms-full.txt`, ~500 КБ |
| NestJS             | один файл `llms-full.txt`, ~2,5 МБ |
| TypeORM            | один файл `llms-full.txt`, ~600 КБ |
| React              | 179 страниц в markdown             |
| Mantine            | индекс + полный справочник         |
| `@effector/router` | постранично, лежит в репозитории   |

Искать по ним удобнее всего грепом:

```bash
grep -n 'createParamDecorator' docs/stack/nestjs/llms-full.txt | head
```

Документации Farfetched в машиночитаемом виде нет. Вместо неё — выжимка в
`.claude/skills/effector-ecosystem/references/04-farfetched-contracts.md` и
наши собственные модели, которые все устроены одинаково.

Эти файлы не коммитятся в репозиторий (мегабайты чужого текста), но попадают
в офлайн-архив.
