# Чеклист самопроверки по критериям оценивания

Проверять **перед сдачей**, по порядку. У каждого пункта есть способ
убедиться — команда или конкретное действие в браузере. «Вроде работает» не
считается: эксперт будет смотреть именно так.

Баллы — из КИМ 09.02.07-3-2027, Том 1 (75 баллов инвариантной части).

---

## Быстрая проверка одной командой

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm e2e
```

Девять сквозных проверок покрывают основной сценарий целиком. Если они
зелёные — каркас цел, и дальше можно проверять то, что автоматикой не
ловится: внешний вид, тексты, поведение на узком экране.

## Задание 1

### Разработка подсистем безопасности ИС — 16 баллов

Самый дорогой критерий. Проверять придирчивее всего.

| Что                                          | Как убедиться                                                                                                                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Регистрация работает                         | `/register`, заполнить форму, кнопка **«Создать пользователя»**                                                                   |
| Логин: латиница и цифры, не менее 6 символов | ввести `abc` → ошибка под полем                                                                                                   |
| Пароль: минимум 8 символов                   | ввести `1234` → ошибка под полем                                                                                                  |
| ФИО: только кириллица и пробелы              | ввести `Ivanov` → ошибка под полем                                                                                                |
| Телефон строго `8(XXX)XXX-XX-XX`             | ввести `89991234567` → ошибка под полем                                                                                           |
| Почта проверяется                            | ввести `qwe@` → ошибка под полем                                                                                                  |
| Та же валидация на сервере                   | `curl -X POST localhost:3000/api/auth/register -H 'Content-Type: application/json' -d '{"login":"ab"}'` → 400 с разбором по полям |
| Пароль не хранится открытым                  | `psql … -c 'select password_hash from users limit 1'` → строка вида `scrypt$…`, пароля не видно                                   |
| Повторный логин отбивается                   | зарегистрировать существующий логин → «Пользователь с таким логином уже существует»                                               |
| Неверные данные при входе                    | `/login` с чужим паролем → «Неверный логин или пароль»                                                                            |
| Сессия в httpOnly cookie                     | DevTools → Application → Cookies → `conf_session`, флаг HttpOnly стоит                                                            |
| Гостя не пускают                             | открыть `/applications` без входа → перекидывает на `/login`                                                                      |
| Пользователя не пускают в админку            | войти обычным пользователем, открыть `/admin` → доступа нет                                                                       |
| Админ входит по данным из ТЗ                 | `Conf2027` / `Demo77` → панель администратора                                                                                     |
| Выход закрывает доступ                       | выйти, вернуться на `/applications` → снова форма входа                                                                           |
| Перебор паролей ограничен                    | десять неверных попыток подряд → «Слишком много попыток»                                                                          |

Разбор решений — [ADR-0004](./adr/0004-authentication.md) и
[ADR-0005](./adr/0005-validation.md).

### Произведение разработки модулей ИС — 6 баллов

| Что                           | Как убедиться                                                          |
| ----------------------------- | ---------------------------------------------------------------------- |

| Отзыв нельзя оставить дважды  | повторная отправка → «Отзыв об этом мероприятии уже оставлен»          |
| ER-диаграмма в рабочей папке  | `docs/er/schema.png` — **требование задания, легко забыть**            |

## Задание 3

### Разработка интерфейса пользователя — 15 баллов

Второй по весу критерий.

| Что                                       | Как убедиться                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------ |
| Тексты кнопок и ссылок **дословно из ТЗ** | «Создать пользователя», «Еще не зарегистрированы? Регистрация» — сверить посимвольно |
| Ошибки показываются у полей               | не алертом и не в консоли                                                            |
| Состояние загрузки видно                  | кнопка блокируется и показывает загрузку                                             |
| Пустые списки объяснены                   | «заявок пока нет» и «ничего не нашлось» — разные тексты                              |
| Навигация очевидна                        | из любой страницы понятно, куда идти дальше                                          |
| Формы не теряют ввод                      | ошибка сервера не стирает заполненное                                                |
| Несуществующий адрес объяснён             | открыть `/такой-страницы-нет` → экран 404 с кнопкой выхода                           |
| Падение не оставляет белый экран          | граница ошибок показывает 500 с кнопкой «Обновить страницу»                          |
| Клавиатура работает                       | по форме можно пройти табом, отправить Enter                                         |

### Разработка веб-приложения в соответствии с ТЗ — 10 баллов

| Что                        | Как убедиться                                                     |
| -------------------------- | ----------------------------------------------------------------- |
| Приложение собирается      | `pnpm build` без ошибок                                           |
| Типы сходятся              | `pnpm typecheck` чисто                                            |
| Линтеры чисты              | `pnpm lint` и `pnpm lint:fsd`                                     |
| Тесты зелёные              | `pnpm test` — 19 на бэкенде, 29 на фронтенде                      |
| Сквозной сценарий работает | `pnpm e2e` — девять проверок                                      |
| Архитектура объяснима      | FSD на фронтенде, модули NestJS на бэкенде, ADR на каждое решение |

## Организационное — проверить обязательно

Эти пункты баллов не приносят напрямую, но их потеря обнуляет работу.

- [ ] **Коммит в начале каждого задания** — требование КИМ;
- [ ] **Коммит в конце каждого задания** — требование КИМ;
- [ ] ER-диаграмма сохранена в рабочей папке проекта;
- [ ] работа лежит там, где указал эксперт, а не только в домашнем каталоге;
- [ ] приложение запускается **с нуля по инструкции**, а не только из вашей
      уже прогретой консоли — проверить по [offline.md](./offline.md);
- [ ] администратор `Conf2027` / `Demo77` заведён — без него эксперт не
      проверит половину функционала.
